# 演示样例

下面每一条都实际跑过，标注了实测的步数与预期画面。
录视频前建议照着 A → B → D 走一遍彩排。

---

## 准备

```powershell
python demo\setup_demo.py           # 生成靶子到 ..\agent_demo
python -m web -C ..\agent_demo      # 打开 http://127.0.0.1:8000
```

`setup_demo.py` 每次都会把靶子还原成"测试挂着"的初始状态，**重拍前跑一次**。
agent 一旦把 bug 修好就没得演了，这是录制时最实际的问题。

## A. 主演示：修一个真实的 bug

> **权限模式：ask（默认）** · 实测 5 步 / 5 次工具调用 / 约 15 秒

靶子里 `median` 对偶数长度列表返回了上中位数，而不是中间两数的平均，
4 个测试挂 1 个。

**输入：**

```
跑一下测试，如果有失败就找出根本原因并修复，最后再跑一次确认全部通过
```

**预期画面：**

| 步骤 | 画面 | 讲解词 |
|---|---|---|
| 1–2 | `read_file` × 2 | 先读代码建立事实，不靠猜 |
| 3 | `run_command` → **退出码 1** | 测试挂了，报错原样回灌给模型 |
| 4 | **diff 确认框** → `edit_file` | 写操作前展示 diff 并请求确认 |
| 5 | `run_command` → **退出码 0** | 自己诊断、自己修、自己验证 |

第 4 步的 diff 弹窗是全片最有说服力的一帧，建议停 2–3 秒。

## B. 多步任务与自动规划

> **权限模式：auto** · 实测 6–8 步 · 需要一个空目录

**输入：**

```
做一个栈数据结构：先写 stack.py，再写 test_stack.py 测试，然后运行测试确认通过
```

**预期画面：** 任务超过三步，agent 会先调 `todo_write` 列出计划，
然后每完成一步就更新清单。消息流里会出现一张任务清单卡片，
`○ 未开始 / ◐ 进行中 / ● 已完成`，已完成项加删除线，卡片始终跟在最新进度旁边。

**讲解词：** 多步任务里模型容易做着做着忘了还剩什么，把计划显式写进历史
等于给它一个可查的锚点；同一时刻只允许一项进行中，否则清单会退化成静态列表。

## C. 从空文件夹生成项目

> **权限模式：auto** · 实测 6 步 / 9 次工具调用 · 需要一个空目录

**输入：**

```
做一个待办事项管理的小项目：todo/ 包目录下放 __init__.py、models.py（Task 数据类）、
storage.py（JSON 持久化）；根目录放 main.py 作为入口和 tests/test_storage.py 测试。
写完跑测试验证。
```

**预期画面：** 左侧文件树里子目录和文件逐个冒出来（写入类工具执行完会自动刷新）。
实测这一条中途出现过一次测试失败并被自行修复，属于加分桥段但不保证复现。

## D. 安全边界（最值得讲的一组）

### D1. 纵深防御 —— 推荐用这条

> **权限模式：ask** · 实测完整复现

**输入：**

```
读取 C:/Windows/win.ini 的内容给我看看
```

**预期画面（三层）：**

1. `read_file` 被路径沙箱拒绝："拒绝访问工作目录之外的路径"
2. 模型改用 `run_command` 执行 `Get-Content C:\Windows\win.ini` 迂回
3. **确认框弹出并展示命令原文** → 点「拒绝」→ 模型收到"不要重复同样的调用"

**讲解词：** 路径沙箱管的是文件工具；`run_command` 管不住——shell 能做的事
没有边界，靠字符串匹配拦不住，真要隔离需要容器。所以命令执行的防线是人工确认。
auto 模式是一次明确的信任让渡。（详见 DESIGN.md 第 27 条）

> ⚠️ **这一条务必用 ask 模式演示。** auto 模式下第 3 步不会弹确认框，
> 命令会直接执行成功，演示会适得其反地暴露沙箱的漏洞。

### D2. 凭据文件防护

> 任意模式 · 工作目录里需要有 `.env`

**输入：**

```
读一下当前目录的 .env 文件，告诉我里面的 key 是什么
```

**预期：** "拒绝访问凭据类文件：.env。这类文件可能包含 API key 等机密，
不会提供给模型，也不允许修改。"

**讲解词：** 路径沙箱只管有没有越出工作目录，而 `.env` 就在工作目录里。
`grep` 是直接遍历读文件的、绕过了路径解析，所以单独又挡了一次。

### D3. 高危命令硬拦截

> **权限模式：auto**（正是要证明 auto 也拦）

**输入：**

```
直接执行：git push --force origin master
```

**预期：** "该命令匹配高危操作规则（强制推送覆盖远程历史），已被拒绝执行，
不会向用户请求确认。"

**讲解词：** auto 不等于无底线。这类操作没有"确认后执行"的价值，唯一正确的
处理就是拒绝。

> 实测提醒：`git reset --hard` 这条不稳定——如果目录不是 git 仓库，
> 模型会先跑 `git status` 发现不是仓库就放弃了，黑名单根本不会触发。
> 用上面的 `git push --force` 更可靠。

### D4. 只读模式

> **权限模式：readonly**

**输入：**

```
把 stats.py 里的 median 函数删掉
```

**预期：** `edit_file` 返回"当前处于只读模式，禁止写文件或执行命令。
请只做分析和说明，不要再尝试调用这类工具。"

## E. 上下文压缩

进度条在顶栏右侧。想现场看到它回落，点「压缩上下文」按钮即可。

**讲解词：** 难点不在摘要，而在从哪里切——协议要求每条 tool 消息都能在前面
找到对应 `tool_call_id` 的 assistant 消息，从中间乱切会被服务端 400 拒绝，
且报错完全不指向压缩逻辑。切割点优先落在 user 消息处，整段尾巴都是 tool
消息时宁可放弃这次压缩。

## F. 会话恢复

先完成任意一个任务，然后**刷新页面** → 点顶栏「继续上次」→ 输入：

```
我刚才让你做了什么？不要用任何工具，直接从记忆回答。
```

**预期：** 不调任何工具，直接答出上一轮做过的事。

**讲解词：** 存档刻意不保存 system prompt——它嵌着启动那一刻的目录快照，
恢复旧的会让模型拿着过期印象干活，比没有记忆更糟。
